# Cap Collective — Continuity & Handover Guide
### Keep the Program Alive When People Leave
**End-of-year close-out, leadership succession, summer maintenance, credentials, and a clean new-year reset.**

---

# PART 1: WHY THIS MATTERS
Most school programs die when their founder graduates or transfers. This guide makes Cap Collective **bigger than any one person.**

**Golden rule:** *Assume the lead leaves tomorrow. Would the program survive? If not, fix it now.*

---

# PART 2: THE LIVING BINDER (Single Source of Truth)
Keep one shared, backed-up location (Drive/SharePoint) containing:
```
/Cap Collective
  ├── README (start here)
  ├── All kit docs (00-28)
  ├── /csv  (data)
  ├── /cad  (designs)
  ├── /resources (code)
  ├── /data-archive (past years)
  ├── /photos (with releases)
  ├── /grants (awarded + reports)
  └── PASSWORDS → use a password manager, NOT this folder
```
**Rule:** If it's not written down in the binder, it doesn't exist.

# PART 3: END-OF-YEAR CLOSE-OUT CHECKLIST
*(Do this in the final 3 weeks of the school year.)*

## Data & Records
☐ Close the year's data; **freeze** a copy in `/data-archive/[year]`
☐ Export Command Center tabs to CSV/PDF
☐ Generate the **Annual Report** (`23_...`)
☐ Log all certifications; note who expires when
☐ Back up the dashboard and sensor data

## Physical Assets
☐ Clean and service all machines
☐ Inventory equipment against the asset list (`14_...`)
☐ Note repairs needed over summer
☐ Store tools/PPE safely; secure the room
☐ Photograph the current setup for next year

## Financial
☐ Reconcile all accounts
☐ Close the P&L; report net to admin
☐ Note remaining balance and where it's held
☐ File all receipts; scan to Drive

## People & Knowledge
☐ Succession decided (who leads next year?)
☐ Handover meeting held (see Part 4)
☐ Graduating seniors recorded as alumni mentors
☐ Recognize everyone (awards assembly)

---

# PART 4: HANDOVER MEETING AGENDA (2 hours)
```
1. Program recap — what worked, what didn't (30 min)
2. Walk the Living Binder folder-by-folder (20 min)
3. Live demo: dashboard, sensor, POS, forms (20 min)
4. Open items & risks (15 min)
5. Credentials transfer (15 min)
6. Next-year calendar draft (15 min)
7. Q&A + contacts exchanged (5 min)
```
**Record it.** Give the next lead the recording.

# PART 6: LEADERSHIP SUCCESSION (Students)
- **Never** let the program depend on seniors.
- Use **grade pyramid:** seniors → juniors → sophomores → freshmen.
- Each lead role has a **co-lead one grade below.**
- Seniors mentor replacements for **one full term.**
- Keep an **alumni mentor list** (they can advise remotely).

```

Role            | Current      | Successor    | Train # done
----------------|--------------|--------------|-------------
```

# PART 8: NEW-YEAR RESET (Fresh Start, Keep History)

## First 2 Weeks
☐ Re-verify all certifications (expired → re-certify)
☐ Re-launch with the assembly (`19_...`)
☐ Re-set leaderboards to zero (but show last year's total as a wall of fame)
☐ Onboard new students via `22_...`
☐ Confirm budget + roles
☐ Test all equipment; log issues

## Preserve vs Reset
| Keep | Reset |
|------|-------|
| Procedures & SOPs | Points/leaderboards |
| Branding | Season-specific goals |
| Equipment | Roster |
| Historical data (archive) | Active spreadsheets |
| Partnerships | Campaign themes |

---

# PART 9: THE FOUNDER-IN-RESIDENCE ROLE
When a beloved lead leaves, give them a light ongoing role:
- Remote mentor for 1 term
- Guest speaker / judge
- Grant advisor
- Alumni reference for college apps

**Benefit:** continuity + a proud alumni network.

---

# PART 10: IF THE PROGRAM GOES DORMANT (Recovery Plan)
If it stops (staff loss, budget cut):
1. **Don't sell the equipment** — store it (this kit's asset list helps).
2. Keep the Living Binder intact.
3. Find one champion willing to restart.
4. Restart at **Tier 1** (collect + wash) — low cost, low risk.
5. Re-launch using `19_...`; rebuild certification.

**A dormant program with good docs restarts easily. A chaotic one doesn't.**
